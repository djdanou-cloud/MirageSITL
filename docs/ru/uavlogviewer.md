Русское зеркало. [Английский источник](../decisions/uavlogviewer.md).

TASK-130 (S14), решение D-04 в [плане фазы 1](PHASE1_PLAN.md). Эта запись
определяет исходный UAVLogViewer, закрепляет его версию, перечисляет, что мешает
ему работать офлайн, и выбирает, как MirageSITL добавляет возможности S14.
Замещающий просмотрщик не создаётся.

Статус: решено (D-04, TASK-130 выполнена 2026-10-28). Закреплённая сборка
открывает лог DataFlash ArduCopter 4.6.2 стейкхолдера в Chromium при полностью
заблокированной сети, без ошибок. TASK-179 (выполнена 2026-11-05) применяет
патчи 0000–0002, воспроизводимо собирает просмотрщик и встраивает его во вкладку
Analysis; на эталонном M5 он открывает логи DataFlash без единого сетевого
запроса в Google Chrome 156.

## Код, который затрагивают возможности S14

* `src/components/Globals.js` хранит состояние ровно одного лога: сообщения,
  смены режимов полёта, события и параметры.
* `src/components/SideBarFileManager.vue` загружает один файл в разбирающий Web
  Worker. Он также открывает лог, указанный в `?file=URL`, и принимает оконное
  сообщение `message` типа `arrayBuffer` от любого источника без проверки origin.
* `src/components/Plotly.vue` рисует графики и их аннотации для событий, смен
  режима и изменений параметров. Изменения параметров берутся из сообщений
  `PARM` через `src/tools/dataflashDataExtractor.js` и `src/tools/paramseeker.js`.
* `src/components/widgets/CesiumSettingsWidget.vue` сравнивает источники
  траектории внутри одного загруженного лога.

API плагинов или расширений нет, и одновременная работа с двумя логами не
поддерживается.

## Решение: способ расширения

MirageSITL ведёт **серию патчей поверх закреплённого коммита исходного проекта**.
Он собирает исправленный просмотрщик локально и встраивает его в просмотр логов
MirageSITL как страницу, раздаваемую с той же машины, которая общается с
MirageSITL через интерфейс сообщений с проверкой origin. MirageSITL не ведёт
расходящуюся ветку-форк и не создаёт замещающий просмотрщик.

Почему:

* У исходного проекта нет точек расширения, поэтому одним встраиванием нельзя
  добавить сравнение двух логов, сдвиг времени или маркеры параметров с цветом по
  статусу.
* Серия патчей сохраняет каждое изменение небольшим и проверяемым. Её можно
  заново применить к более новому коммиту, а отдельные патчи — предложить в
  исходный проект.
* GPL версии 3 разрешает изменять просмотрщик и локально встраивать его; файлы
  патчей являются опубликованным исходным кодом изменений.

Патчи хранятся в `third_party/uavlogviewer/patches/` и применяются сборкой
TASK-179 в порядке имён. Патчи 0–2 существуют (TASK-179); остаток патча 2 и
патчи 3–4 относятся к TASK-180 и TASK-181:

| Патч | Назначение | Изменяемые файлы исходного проекта |
| --- | --- | --- |
| 0 Совместимость (`0000-compatibility.patch`, TASK-179) | Допускать сообщения `CMD` без поля `Frame` (логи старых прошивок), чтобы извлечение миссии больше не прерывало остальные шаги извлечения. ## Офлайн-сборка и встраивание (TASK-179)

`node scripts/build-uavlogviewer.mjs [--source DIR] [--out DIR] [--work DIR]`
сверяет checkout исходников с lock (по умолчанию checkout TASK-152 в
`<launcher home>/sources/uavlogviewer`), копирует его в новый рабочий каталог,
применяет патчи через `git apply`, выполняет `npm ci --ignore-scripts` (npm
проверяет каждый хеш целостности lock-файла), исходный шаг `patch-package` и
`npm run build` с пустым токеном Cesium, `UAVLOGVIEWER_COMMIT` и
`SOURCE_DATE_EPOCH`, равным времени исходного коммита. Выходной каталог (по
умолчанию `<launcher home>/uavlogviewer`) содержит собранный просмотрщик,
`licenses/` (тексты GPL-3.0 просмотрщика и парсера, патчи, README с указанием
соответствующего исходного кода и `THIRD-PARTY-NOTICES.txt` с лицензией каждого
из 958 production-пакетов npm) и `build-manifest.json` (коммит, хеши патчей,
toolchain и дайджест вывода по правилу TASK-130 без самого манифеста).
`scripts/install-macos.mjs` запускает её на шаге 5 и пропускает, если манифест
по-прежнему совпадает с серией патчей и файлами на диске. Lock фиксирует
воспроизведённую сборку в `patchedBuild`. Сеть (реестр npm) нужна только сборке.

Dev- и preview-серверы Vite раздают сборку по `/uavlogviewer/` из
`MIRAGE_UAVLOGVIEWER_DIR` (по умолчанию `<launcher home>/uavlogviewer`) только
loopback-клиентам, для GET и HEAD, с COOP `same-origin`, COEP `require-corp` и
CORP `same-origin`, отказывая в путях вне каталога. Вкладка Analysis
(`apps/web/src/analysis/LogViewerHost.tsx`) загружает просмотрщик только при
первом открытии вкладки, показывает коммит сборки и число патчей со ссылкой на
каталог лицензий и объясняет, как установить просмотрщик, если сборка не
раздаётся. Выбранный файл отклоняется, если это не двоичный лог DataFlash
(заголовок `0xA3 0x95`, не более 512 МиБ), и затем передаётся во фрейм.

Интерфейс сообщений, протокол 1. Обе стороны принимают сообщение только от того
же origin и ожидаемого окна (просмотрщик — от родителя, хост — от фрейма) и
отправляют с целевым origin, равным собственному:

| Направление | Сообщение | Значение |
| --- | --- | --- |
| Хост → просмотрщик | `{ type: "mirage.loadLog", protocol: 1, name, bytes }` | Открыть `bytes` (ArrayBuffer, передаётся с переносом владения) как лог DataFlash с именем `name` (1–255 символов без разделителей пути и управляющих символов) |
| Просмотрщик → хост | `{ type: "mirage.ready", protocol: 1 }` | Просмотрщик слушает; выбранный ранее лог отправляется сейчас |
| Просмотрщик → хост | `{ type: "mirage.logAccepted", protocol: 1, name, bytes }` | Лог передан парсеру |
| Просмотрщик → хост | `{ type: "mirage.logRejected", protocol: 1, reason }` | Сообщение отклонено, например из-за другой версии протокола |
| Просмотрщик → хост | `{ type: "mirage.logParsed", protocol: 1, name, messageTypes }` | Разбор завершён с указанным числом типов сообщений |

Парсер DJI (`src/tools/parsers/djiParser.js`) по-прежнему запрашивает ключи
расшифровки у `dev.dji.com` при открытии лога DJI `.txt`. Фаза 1 открывает
только логи ArduPilot; офлайн smoke-тесты этого кода не достигают.

## Путь адаптера для экспериментов MirageSITL

Эксперименты MirageSITL попадают в просмотрщик в формате DataFlash, который его
парсер уже читает:

* Лог DataFlash ArduPilot, записанный для каждого эксперимента (TASK-164),
  открывается как есть.
* Собственные записи MirageSITL записываются в DataFlash модулем записи TASK-178.

Контекст эксперимента (версии профиля и компонентов, условия среды и история
параметров со статусом запроса) передаётся через интерфейс сообщений патча 2, а
не внутри лога. Внешний лог без этого контекста показывает его как неизвестный;
история параметров, которой нет в логе, никогда не придумывается.
