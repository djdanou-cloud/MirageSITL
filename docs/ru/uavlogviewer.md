# Решение об интеграции UAVLogViewer

Русское зеркало. [Английский источник](../decisions/uavlogviewer.md).

TASK-130 (S14), решение D-04 в [плане фазы 1](PHASE1_PLAN.md). Эта запись
определяет исходный UAVLogViewer, закрепляет его версию, перечисляет, что мешает
ему работать офлайн, и выбирает, как MirageSITL добавляет возможности S14.
Замещающий просмотрщик не создаётся.

Статус: решено (D-04, TASK-130 выполнена 2026-10-28). Закреплённая сборка
открывает лог DataFlash ArduCopter 4.6.2 стейкхолдера в Chromium при полностью
заблокированной сети, без ошибок. Та же проверка в Chrome на macOS выполняется
на M5 в рамках TASK-179.

сборка записывает `runtime-config.js` с пустым токеном. Встроенный пример — это
лог телеметрии (`src/assets/vtol.tlog`), а не лог DataFlash.

## Код, который затрагивают возможности S14

* `src/components/Globals.js` хранит состояние ровно одного лога: сообщения,
  смены режимов полёта, события и параметры.
* `src/components/SideBarFileManager.vue` загружает один файл в разбирающий Web
  Worker. Он также открывает лог, указанный в `?file=URL`, и принимает оконное
  сообщение `message` типа `arrayBuffer` от любого источника без проверки origin.
* `src/components/Plotly.vue` рисует графики и их аннотации для событий, смен
  режима и изменений параметров. Изменения параметров берутся из сообщений
  `PARM` через `src/tools/dataflashDataExtractor.js` и `src/tools/paramseeker.js`.
* `src/components/widgets/CesiumSettingsWidget.vue` сравнивает источники
  траектории внутри одного загруженного лога.

API плагинов или расширений нет, и одновременная работа с двумя логами не
поддерживается.

## Решение: способ расширения

MirageSITL ведёт **серию патчей поверх закреплённого коммита исходного проекта**.
Он собирает исправленный просмотрщик локально и встраивает его в просмотр логов
MirageSITL как страницу, раздаваемую с той же машины, которая общается с
MirageSITL через интерфейс сообщений с проверкой origin. MirageSITL не ведёт
расходящуюся ветку-форк и не создаёт замещающий просмотрщик.

Почему:

* У исходного проекта нет точек расширения, поэтому одним встраиванием нельзя
  добавить сравнение двух логов, сдвиг времени или маркеры параметров с цветом по
  статусу.
* Серия патчей сохраняет каждое изменение небольшим и проверяемым. Её можно
  заново применить к более новому коммиту, а отдельные патчи — предложить в
  исходный проект.
* GPL версии 3 разрешает изменять просмотрщик и локально встраивать его; файлы
  патчей являются опубликованным исходным кодом изменений.

Запланированные патчи хранятся в `third_party/uavlogviewer/patches/` и
применяются сборкой TASK-179:

| Патч | Назначение | Изменяемые файлы исходного проекта |
| --- | --- | --- |
| 0 Совместимость | Допускать сообщения `CMD` без поля `Frame` (логи старых прошивок), чтобы извлечение миссии больше не прерывало остальные шаги извлечения | `src/tools/dataflashDataExtractor.js` |
| 1 Офлайн | Удалить аналитику и веб-шрифты, встроить значки, заменить онлайн-проверку настройкой, удалить поставщика со встроенным ключом, отключить геолокацию по IP офлайн | `index.html`, `src/App.vue`, `src/components/Home.vue`, `src/components/CesiumViewer.vue`, `src/components/widgets/MagFitTool.vue`, `package.json` |
| 2 Интерфейс сообщений | Заменить непроверяемый обработчик `message` на API с проверкой origin: загрузить лог с именем и контекстом, загрузить второй лог, задать сдвиг времени, добавить маркеры изменений параметров со статусом «запрошено», «подтверждено» или «отклонено», показать контекст эксперимента | `src/components/SideBarFileManager.vue`, `src/components/Home.vue`, новый `src/mirage/bridge.js` |
| 3 Два лога | Хранить отдельный набор данных для каждого лога, разбирать второй лог в собственном worker, рисовать кривые каждого лога своим стилем на общих осях рядом или наложением с ручным сдвигом времени; выбирать два интервала одного лога | `src/components/Globals.js`, `src/components/SideBarFileManager.vue`, `src/components/Plotly.vue`, `src/components/PlotSetup.vue`, `src/components/Sidebar.vue` |
| 4 Маркеры и контекст | Окрашивать аннотации изменений параметров по статусу; показывать версии аппарата и компонентов, условия среды и различия параметров, помечая отсутствующий контекст как неизвестный | `src/components/Plotly.vue`, `src/components/Sidebar.vue`, новый `src/mirage/ContextPanel.vue` |

## Путь адаптера для экспериментов MirageSITL

Эксперименты MirageSITL попадают в просмотрщик в формате DataFlash, который его
парсер уже читает:

* Лог DataFlash ArduPilot, записанный для каждого эксперимента (TASK-164),
  открывается как есть.
* Собственные записи MirageSITL записываются в DataFlash модулем записи TASK-178.

Контекст эксперимента (версии профиля и компонентов, условия среды и история
параметров со статусом запроса) передаётся через интерфейс сообщений патча 2, а
не внутри лога. Внешний лог без этого контекста показывает его как неизвестный;
история параметров, которой нет в логе, никогда не придумывается.

## Осталось

* **Chrome на macOS.** TASK-179 выполняет ту же проверку в Chrome на эталонном
  M5 (решение A-01), когда встраивает исправленный просмотрщик, например с
  `CHROMIUM_PATH`, указывающим на исполняемый файл Chrome.
* **Старые логи.** Логи прошивок, которые не записывали `CMD.Frame`, не
  проходят, пока патч 0 не появится в TASK-179.
