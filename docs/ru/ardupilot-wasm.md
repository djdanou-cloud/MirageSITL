# Решение об осуществимости ArduPilot в браузере
<!-- source-sha256: c464acae0a0c39ccf621964bc82bd11373938728ee4c83dba17087a9412cdbb1 -->

Решение (пересмотрено 2026-10-17 в TASK-045): прошивка собирается и выполняется как WebAssembly, но интеграция с браузером MirageSITL остаётся открытой. Исследовательская проверка TASK-044 изучила четыре файла HAL и не заметила, что ArduPilot на закреплённом коммите 8ab6afde107a91df1b5f60ade8f333cb8a61b190 уже содержит штатную плату `wasm` (`libraries/AP_HAL_SITL/hwdef/wasm`, `HAL_SITL_WASM_ENABLED`, инструментарий Emscripten, pthreads через `PROXY_TO_PTHREAD` и экспортируемый байтовый мост последовательного порта). CI проекта ArduPilot собирает эту плату и запускает в Node smoke-тест MAVLink. Коммит совпадает с JSON-оракулом TASK-041, а пути и хеши исходников закреплены в native/ardupilot/source.lock.json.

| Возможность | Наблюдаемое свидетельство | Требуемая работа |
| --- | --- | --- |
| Планировщик | Штатная плата wasm выполняет потоки SITL как pthreads Emscripten (общая память, пул из 4 Worker) | Синхронизация с временем симуляции MirageSITL и ограниченное завершение внутри приложения (TASK-046) |
| UART/сеть | `--serial0 wasm` направляет порт через экспортируемые `ardupilot_serial_write/read/read_available`; сеть и UDP RC отключены; TCP-порты нужно задать как `none` | Подключить мост к MAVLink/Worker-mailbox MirageSITL (TASK-046) |
| Хранилище | Файловая система Emscripten; при первом запуске виртуальный EEPROM стирается и инициализируется в памяти | Постоянное хранение параметров, атомарная инициализация и восстановление после перезапуска Worker |
| Компилятор | Закреплённый emsdk 4.0.15 собирает ArduCopter для `--board wasm` на хосте WSL Ubuntu; три чистые сборки побайтно совпадают | CI ArduPilot использует Emscripten 6.0.8; смена версии проекта — отдельное решение |
| Браузерная память | Импортируемая общая память: 256 начальных и 32768 максимальных страниц (от 16 МиБ до 2 ГиБ, рост разрешён); допуск проверяет пределы против бюджета | Проверить артефакт в браузерном Worker с COOP/COEP и измерить память под нагрузкой |
| Лицензии | GPL-3.0-or-later; артефакты хранятся вне репозитория (`local-only-pending-gpl-review`) | Проверить обязательства прошивки/зависимостей до распространения артефакта (BLOCKED_DECISION) |
| Паритет | Нативный ELF ArduCopter SITL и WASM-артефакт теперь собираются из одного исходника; драйвера полёта и сравнения трасс пока нет | Native/WASM arm/takeoff/land/failsafe и паритет траектории 30 с (TASK-047) |

Запуск: node scripts/probe-ardupilot-wasm.mjs фиксирует возможности (код 2, пока нет интеграции с браузером), node scripts/build-ardupilot-wasm.mjs собирает артефакт и манифест, node scripts/smoke-ardupilot-wasm.mjs DIR проверяет и запускает его. MIRAGE_ARDUPILOT_SOURCE проверяется по хешам отдельных файлов, MIRAGE_EMCC задаёт явный компилятор. Запуск в Node показывает, что прошивка работает; это не свидетельство браузера, сопряжения с физикой или полёта.


Решение продолжения (2026-10-19): свежая чистая сборка 4.0.15 воспроизводит закреплённые байты; настоящий Chromium теперь запускает проверенный артефакт в изолированном выделенном Worker с четырьмя pthread. Локальный bootstrap проверяет 16 МиБ начальной общей памяти в пределах 2 ГиБ, HEARTBEAT с правильным CRC, сохранение параметра при штатном/внезапном перезапуске, атомарные IndexedDB-checkpoint и очистку собственных Worker. Это заменяет исторические требования Worker/хранилища таблицы выше для допуска локального bootstrap. Сопряжение планировщика/flight HAL и production-mailbox остаётся TASK-046; паритет нативного/WASM-полёта — TASK-047. Существующий GPL-review распространения остаётся открытым, артефакт по-прежнему local-only-pending-gpl-review. Из запуска не выводятся миграция версии компилятора или допуск production-режима полёта.
