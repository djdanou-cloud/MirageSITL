# Возможность нативного SITL на macOS (TASK-127)

Английский источник: [macos-sitl.md](../decisions/macos-sitl.md).

Статус: PASS на 2026-10-29. Запись содержит доказательства нативного
запуска для D-02; она не выбирает виртуальную машину/контейнер или пакет выпуска.
Путь фазы 1: штатный ArduCopter на Apple Silicon, драйвер с владением процессами
на Node 24, sidecar pymavlink 2.4.50 и Rust WASM тела MirageSITL. Самолёт здесь —
существующий синтетический quad X, а не модель измеренного реального аппарата.

## Контракт исполняемого файла и владения

Исходники должны быть чистыми на коммите из `scripts/sitl.lock.json`, включая
инициализированные подмодули на закреплённых ревизиях. Перед запуском проверяются
коммит и переданные SHA-256 бинарника/драйвера. Бинарник должен быть обычным файлом
с разрешением исполнения. `scripts/sitl/native-binary.ts` принимает тонкий
little-endian Mach-O64 `MH_EXECUTE` архитектуры хоста macOS либо соответствующий
ELF64 EXEC/PIE на Linux. Проверяются полные таблицы команд/программных заголовков,
границы сегментов в файле, исполняемый код и команда входа Mach-O. Файлы лишь
с магическим числом, библиотеки, скрипты, неверные архитектуры и усечённые таблицы
отклоняются. Universal/fat Mach-O и 32-битные бинарники вне этого контракта.

Родитель создаёт выделенную группу POSIX. Дедлайн, переполнение вывода и выход
драйвера завершают эту группу, включая потомков с уже закрытыми каналами вывода;
чужие процессы остаются вне группы. Прошивка и Python-sidecar используют частные
рабочие каталоги и выделенные loopback-порты. Каталог захвата должен быть новым;
неудачные попытки сохраняются отдельно. Драйвер записывает хост/формат, хеширует
исполняемый файл и все входные исходники и проверяет неизменность исходников
после выполнения. Старые захваты Linux остаются историческими; новое поле хоста
не нарушает их схему.

## Локальная штатная сборка

Используются свежий checkout и отдельные каталоги сборки/виртуального окружения.
Патчи прошивки не применяются, включая опциональный патч пола шума IMU.
Ниже проверяемый локальный рецепт; первоначальная загрузка зависимостей требует
сети. Системный Python и файлы инициализации оболочки не изменяются.

```bash
# Source is a fresh checkout at this exact commit.
git -C .cache/task-127/ardupilot rev-parse HEAD
# Expected: 8ab6afde107a91df1b5f60ade8f333cb8a61b190
git -C .cache/task-127/ardupilot submodule update --init --recursive --depth 1 modules/waf modules/mavlink modules/gtest modules/gsoap modules/littlefs modules/lwip modules/DroneCAN/DSDL modules/DroneCAN/libcanard modules/DroneCAN/dronecan_dsdlc modules/DroneCAN/pydronecan
python3 -m venv .cache/task-127/venv
.cache/task-127/venv/bin/python -m pip install pymavlink==2.4.50 empy==3.3.4 dronecan==1.0.27 pexpect==4.9.0 pyserial==3.5
cd .cache/task-127/ardupilot
../venv/bin/python waf configure --board sitl --out ../build-stock
../venv/bin/python waf --out ../build-stock copter -j 8
```

Для полёта вернитесь в корень репозитория. Результат сборки —
`.cache/task-127/build-stock/sitl/bin/arducopter`. Сохраняйте журналы настройки/
сборки, полные ревизии подмодулей, список пакетов Python и SHA-256 бинарника.
Переменные полёта и проверки приведены в [runbook](runbook.md);
каталог захвата должен быть новым, отчёты — отдельными.
`MIRAGE_SITL_IMU_NOISE_FLOOR=ardupilot` сохраняет штатные члены ошибок прошивки.

## Приёмка и ограничения

Приёмка использует существующие физику JSON 800 Гц и оцениваемую трассу 100 Гц:
фактические arm, взлёт минимум на 3 м, висение 10 м ±1 м не менее 10 с, затем
посадку ниже 0.5 м с disarm. Проверки arming и EKF3 остаются включены. Каждой
принятой выборке нужна свежая здоровая диагностика автопилота. Дедлайн родителя
сохраняется равным 120 с реального времени. Независимая проверка сырых байтов
MAVLink и аудит захвата должны пройти без несовпадений исходников/идентичностей
и необъяснённых пропусков кадров.

Задача не подтверждает путь 16 моторов (TASK-128), синхронную паузу (TASK-129),
установку launcher (TASK-151/152), измеренную точность модели, READY автопилота
в браузере или производительность реального времени/GPU.

## Наблюдаемый результат — 2026-10-29

PASS на Apple M5, macOS 26.6 (25G72), Xcode command-line tools в
`/Library/Developer/CommandLineTools`, Apple Clang 21.0.0
(`clang-2100.1.1.101`), Node 24.22.1 и Python 3.9.6. Штатная настройка waf
и `copter -j 8` собрали чистые закреплённые исходники без патча. Нативный
arm64 Mach-O: 5 364 104 байта, SHA-256 `d47c1f64934f1911e4d6fb88da8aa18c21c9e438f3ae687b0e56eb13807e08e4`.
Версии инструментария/пакетов/подмодулей и хеши журналов находятся в локальном
`.cache/task-127/build-manifest.json`.

Первые попытки остановились из-за отсутствующих littlefs, компилятора DroneCAN
и lwIP; журналы сохранены как `build-stock-attempt-001.log`–`003.log`.
После инициализации закреплённых зависимостей попытка `004.log` прошла за
84.348 с. Сохраняется предупреждение upstream об устаревшем `-ld_classic`;
политика предупреждений, пределы полёта и функции прошивки ради успеха не менялись.

Итоговый захват — `.cache/task-127/capture-002`; рядом находятся отчёт harness,
`capture-002-audit.json` и `completion.json`. В нём записаны:

* 67 257 кадров физики 800 Гц и 4161 оцениваемая выборка 100 Гц;
* 84.07125 с симуляции за 42.587271542 с реального времени;
* удержание 10.2 с, высота истины 9.763922418321018–9.989905957377403 м,
  автопилота 9.753–9.989 м; конечная истинная высота 0 м, disarm;
* 31 952 исходных наблюдения, сопоставленных pymavlink 2.4.50 с проверенными
  по CRC байтами MAVLink; живой парсер допуска не обнаружил ошибок CRC;
* нулевые счётчики duplicate, gap, dropped, restart, stale, invalid и resend;
  все 6224 ограниченных значения PWM относятся к прогреву и независимо
  пересчитаны по сохранённым пакетам;
* первый нативный READY на 41.27 с симуляции; штатные члены ошибок IMU
  ArduPilot сохранены, случай РЭБ MirageSITL не вводился;
* прошивка завершена ограниченной эскалацией до SIGKILL, Python вышел с кодом 0;
  отсутствие обоих собственных PID проверено после завершения.

Захват `001` тоже прошёл до последнего исправления проверки входа ELF; это
заменённый снимок, не подтверждающий итоговые исходники. Новый тест сначала
воспроизвёл допуск ELF-библиотеки с entry 0, затем прошёл после проверки входа
в исполняемый загружаемый сегмент. Регрессия владения сначала воспроизвела
потомка, устойчивого к TERM и пережившего закрытие каналов; теперь проходит
и проверяет, что чужой процесс остаётся жив.

На итоговом коде проходят: 20 тестов в восьми файлах допуска/владения/полёта/
прогрева, 15 тестов в трёх файлах реального loopback JSON/моста/состояния,
typecheck, сборка web, lint checkout (без посторонних `.claude/worktrees/**`),
двуязычная документация и `git diff --check`. Сборка web сохраняет прежнее
предупреждение о размере чанка. Файлы датчиков TASK-143 и исторические
отслеживаемые `test-results/` не изменены. Сырые захваты, результаты сборки
и локальные отчёты игнорируются; прошивка и внешние исходники не добавлены
в отслеживаемый репозиторий.
