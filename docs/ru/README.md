# MirageSITL

<!-- source-sha256: 8d9173074b3ffdd983df16830e932a26e28d4072e1595b01082db705a3af74b1 -->

Английский источник: [Source of truth](../../README.md). Изменения спецификации обновляют оба языка в одной задаче.


Браузерный проект симуляции БПЛА и подготовки пилотов, начинающийся с
изолированного физического цикла и работающей полётной лаборатории.

Английский язык — источник истины репозитория. Код, UI, комментарии,
тесты, логи, коммиты и первичная документация — на английском. Системная
документация поддерживается на двух языках в одном изменении.

## Текущая реализация

Milestone 01 включает React 19, React Three Fiber/Three.js, Vite, Tailwind CSS
и Lucide UI; отдельный модульный Worker; фиксированное интегрирование 400 Гц;
атомарный SharedArrayBuffer transport; USB Gamepad и калибровку осей;
упрощённую демонстрационную модель квадрокоптера. В интерфейсе есть 3D-сцена,
телеметрия, коллективный газ, arm/disarm, pause/reset, failsafe ввода и
счётчики пропущенных временных интервалов.

Работающее приложение использует бинарный ABI **v2** (TASK-085): epochs сессий,
поля статуса EKF/EW, очереди датчиков/актуаторов и Control Protocol v2. Значения
EKF/EW остаются незаданными, пока не появятся autopilot и движок EW. ABI v1 остаётся
в `packages/protocol` вместе с тестами, но приложение его больше не использует.

JSBSim/BET WASM, ArduPilot SITL/HITL, РЭБ, фотореалистичный terrain,
FPV/thermal и AAR запланированы. Текущая аэродинамика упрощена и не
валидирована для подготовки пилотов.

Основа Phase 0 добавляет детерминированные seeded streams, проверяемые по SHA-256
манифесты синтетических fixtures и строгую проверку моделей/frame/inertia/rotors.
Модели допускаются в неизменяемый реестр сессии; переключение модели runtime
остаётся будущей задачей. Контракты сериализации описаны в руководстве архитектуры.

При запуске проверяются secure context, isolation, SharedArrayBuffer, Worker и
WebGL2. Без обязательных возможностей Start отключён с объяснением; без Gamepad
отключён USB. Ошибка WebGPU probe сохраняет WebGL2. Доступность Serial API
показывается отдельно: HITL и WebGPU rendering ещё не реализованы.

## Быстрый запуск

Node.js **22.13+** или **24 LTS** (`.nvmrc` выбирает 24), npm 10+ и современный
Chrome/Edge на macOS/Windows. Будущий HITL Web Serial нацелен на Chromium.
Облачная задача использует текущий изолированный checkout; новый Git worktree
создаётся только по явному запросу.

```bash
cd /workspace/MirageSITL
npm ci
npm run dev
```

Для локального клона укажите фактический каталог. Dev-сервер использует
порт 5173. Для SharedArrayBuffer нужен secure context: HTTPS или localhost.
Удалённый HTTP по IP не подходит. Vite dev/preview выставляют заголовки;
production hosting настраивает их отдельно:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Если cloud home cache недоступен для записи, добавьте
`--cache /workspace/.cache/mirage-npm` к `npm ci`.

### Демонстрационный полёт

Выберите **Start → Arm motors → поднимите Demo throttle выше 50%**.
Spool response намеренно имеет задержку. Pause отключает двигатели;
верните газ к нулю перед повторным arm. Reset останавливает модель и
возвращает её на землю. Скрытие вкладки ставит сеанс на паузу.

В EdgeTX/OpenTX выберите USB joystick mode, вкладку USB и сдвиньте стик
для обнаружения браузером. Выберите устройство и проверьте направления
при выключенных двигателях. Начальный mapping 0/1/3/2 не универсален.
Таблица задаёт ось, min, center, max и inversion. Калибровка действует до
перезагрузки страницы. Demo работает без аппаратуры. Этот этап не
отправляет команд реальному полётному контроллеру.

## Краткая архитектура

```text
Main Thread: Gamepad/calibration -> SAB pilot mailbox
Physics Worker: fixed-step demo -> SAB state ring
Main Thread: coherent snapshots -> interpolation -> R3F/HUD
```

```text
apps/web/             React UI, R3F view, Worker, runtime coordination
packages/protocol/    ABI v1/v2 and atomic readers/writers
packages/physics/     Demo dynamics and bounded scheduler
packages/input/       Gamepad adapter and calibration
packages/test-support/ Fixture integrity/provenance and deterministic PRNG
tests/                Unit and real-browser functional checks
docs/                 English specifications, roadmap, architecture
docs/ru/              Russian mirrors of system documentation
```

Physics владеет truth и временем симуляции. Main — UI/вводом/рендером.
High-rate данные передаются через SAB, lifecycle/errors — postMessage.
Render ring хранит короткую историю интерполяции, а не AAR archive.
Будущие backends/adapters описаны в спецификациях, а не представлены
пустыми неработающими сервисами.

## Проверка

```bash
npm run check:docs
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Playwright Chromium устанавливается один раз, только если отсутствует.
Подготовленная cloud-среда может использовать системный браузер:

```bash
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

Unit tests проверяют ABI, scheduler, demo dynamics, координаты и калибровку.
Browser tests используют настоящий Worker/SAB, взлёт, pause/reset,
имитацию подключения/отключения USB и mobile layout. Mock USB не
валидирует реальный пульт или Pixhawk.

После сборки `npm run preview -w @mirage/web` запускает production bundle
на порту 4173. Проверьте isolation, Worker READY, движение после arm и
неизменные ticks при pause. Отдельные lint/typecheck команды доступны; Для WASM tests нужны Rust 1.97.0 и wasm32 target;
команды toolchain приведены в CLAUDE.md. GitHub Actions запускает независимые unit/browser/build jobs для PR
и push в main. JUnit unit, JUnit/HTML и failure traces браузера, build logs
и artifacts сохраняются даже после ошибок. Автоматические tooling checks
проверяют unsafe-type fixtures и ненулевой exit status обоих runners при
отсутствии найденных тестов.

400 Гц — фиксированный **интеграционный шаг**, не hard real-time гарантия
браузера. Catch-up ограничен 8 шагами, потери wall time видны в UI.
Целевые 60–120 FPS и 400–1200 Гц требуют production-измерений на Apple
Silicon M4 и RTX 4050; cloud headless smoke их не подтверждает.

Последний повтор: нативные прогоны Rapier/JSBSim с явным `--patched` проходят
миллион шагов с нулём вызовов/байт аллокатора и контрольными суммами траекторий,
совпадающими с оригиналами. Исходные сборки всё ещё выделяют память. Команда
`node scripts/check-engine-patch-parity.mjs` проверяет идентичность отчётов,
исходников и патчей перед сравнением. Патчи сохраняют хранилища, не меняя физику.
Точная область, команды и ограничения приведены в разделе нативных патчей
аллокаций спецификации движков. Результат не сертифицирует production-привязку
Rapier JS/WASM, сборку JSBSim WASM, контактное сопряжение и физическую
достоверность. Блокировки SDK и измеренных данных сохраняются.

Первая измеренная фикстура, `tests/fixtures/contact/nasa-drop.json`, содержит
сбросы шасси на горизонтальную поверхность из NASA TM X-3561
(https://ntrs.nasa.gov/citations/19780003109). Её создал
`tests/fixtures/contact/generate_nasa_drop.py` из хешированного архива Docling
в `tests/fixtures/contact/nasa/` с переводом в SI. На ней сферический контакт
Rapier проходит проверки согласованности импульса, непроникания и энергии. Он
не выполняет измеренные границы замедления (-1.6 g) и хода, поэтому
`validate-models.mjs` сообщает шлюз точности контакта как проваленный.


TASK-037/038/039/040/048/052/053/056/057/060 добавляют закреплённое подмножество
MAVLink2, версионированную калибровку/режимы радио, допуск жизненного цикла
автопилота, loopback WS/UDP с origin/токеном, Serial по жесту пользователя
с отдельным I/O Worker декодирования, изолированные РЭБ/моторные отказы и
политику рельефа с отказом по умолчанию. Активен демо-backend; SITL/HITL,
полная композиция РЭБ и живая загрузка рельефа не включены.

Команда npm run start -w @mirage/bridge требует локальный MIRAGE_BRIDGE_TOKEN
(64 hex); MIRAGE_BRIDGE_ORIGIN, MIRAGE_MAVLINK_PORT и MIRAGE_PHYSICS_PORT
необязательно задают origin/UDP. Не печатать токены, не добавлять их в URL/
репозиторий. Это loopback ws; HTTPS/WSS/PNA требуют отдельной интеграции.
node scripts/bench-links-ew.mjs all 400 (также 800/1200) даёт Node-свидетельство
аллокаций, не аппаратную приёмку времени. Скалярные удобные методы могут
выделять boxed float: в высокочастотной композиции использовать typed-array
входы/выходы из спецификации движков.


## Локальное дополнение теплового конвейера, инструктора и AAR

Demo содержит горизонт NED с явным неизвестным/устаревшим статусом автопилота, консоль инструктора с подтверждениями и ограниченную запись сеанса. Нажмите **Start recording**, выполните полёт demo, затем **Review recording** или **Export session**. **Import AAR** открывает проверенную шкалу снимков, не заменяя активный полёт. Запись прореживает истину/стики из Main с номинальными 10 Гц; потоки датчиков/актуаторов FC в demo отсутствуют. Кольцо на 30 минут использует 9,216,000 байт записей с отдельным учётом потерь и вытеснения. Архив ограничен 32 МиБ, произвольные метаданные/ключи/серийные идентификаторы исключены.

Горячие клавиши инструктора: P — пауза, R — сброс, F — выбранный отказ; фокус ввода подавляет команды. Запросы погоды/отказов/модели показывают фактическое отклонение demo-backend до подключения рабочего backend с поддержкой. Тепловой пакет предоставляет синтетический тепловой баланс, WebGL2 LWIR-материал и детерминированную коррекцию смещения, проверенные независимо от активной сцены. Измеренная точность CADEX не заявляется.

Модули прогрева TASK-043 требуют диагностику самого автопилота; живой полёт/прогрев ArduPilot и зависимые интеграционные допуски UI блокированы TASK-042. Измерение аллокаций производителя записи выполняется `node scripts/bench-aar.mjs 400` (повторить для 800/1200); оно не сертифицирует браузерное планирование или производительность оборудования.

## Локальные инструменты приёмки и обучения

Репозиторий теперь включает построение/владение collision-чанками, детерминированное расписание/рубрики сценариев и локальные инструменты свидетельств SITL/HITL/РЭБ/GPU/системы/выпуска. Независимые модули не включают проверенный production-backend полёта. Отсутствующие драйверы прошивки, FC, целевые GPU, закреплённые EW-трассы и свидетельства чистой машины остаются явными блокировками. TASK-044 фиксирует наблюдаемые требования нативного HAL; TASK-045–047 остаются открыты.

Пользователь клавиатуры может перейти к контролам, видит фокус и однократное сообщение об отказе разрешения. Браузерный пакет включает axe без отключённых правил и проверки overflow/Serial-focus при 390px. Перед доверием к изменению нужны стандартные проверки. Команды, форматы внешних трасс, владение процессами и чеклист доступности описаны в [руководстве](runbook.md). Все новые CLI без входа дают 2 с заблокированным отчётом; автоматической публикации нет.

Существующее сравнение с измерениями NASA по шасси сейчас проваливает диапазоны замедления/хода, хотя численная интеграция проходит. Система/выпуск сохраняют этот физический G2-провал; новое ПО контактную модель не сертифицирует.
