# MirageSITL

<!-- source-sha256: 3fb52a4f439ef7d538e4f2645a4556ab5cb4aa28c0101413de413fa402b97c32 -->

Английский источник: [Source of truth](../../README.md). Изменения спецификации обновляют оба языка в одной задаче.

Браузерный проект симуляции БПЛА и подготовки пилотов, начинающийся с
изолированного физического цикла с фиксированным шагом и работающей полётной
лаборатории.

Английский язык — источник истины репозитория. Исходный код, UI, комментарии,
тесты, логи, коммиты и первичная документация ведутся на английском. Системная
документация поддерживается на двух языках в одном изменении.

## Текущая реализация

Milestone 01 включает React 19, React Three Fiber/Three.js, Vite, Tailwind CSS
и Lucide UI; отдельный модульный Worker; фиксированное интегрирование 400 Гц;
атомарный транспорт SharedArrayBuffer; ввод с USB Gamepad и калибровку осей;
упрощённую демонстрационную модель квадрокоптера. В интерфейсе есть 3D-сцена,
телеметрия, общий газ, arm/disarm, pause/reset, failsafe ввода и счётчики
пропущенных интервалов планировщика.

Работающее приложение использует бинарный ABI **v2** (TASK-085): эпохи сессий,
поля статуса EKF/EW, очереди датчиков и актуаторов и Control Protocol v2. В
браузерном демо значения EKF/EW остаются незаданными, пока в активную полётную
сессию не подключены браузерный автопилот и контур РЭБ (TASK-046, TASK-047,
TASK-074, TASK-075, TASK-078). ABI v1 остаётся в `packages/protocol` вместе со
своими тестами как регрессионный API.

Основа Phase 0 добавляет детерминированные потоки ГПСЧ с фиксированным seed,
проверяемые по SHA-256 манифесты синтетических фикстур и строгую валидацию
моделей, систем координат, тензоров инерции и роторов. Модели допускаются в
неизменяемый реестр сессии; переключение модели во время выполнения остаётся
отдельным интеграционным шагом. Сериализованные контракты описаны в
[руководстве по архитектуре](architecture.md).

При запуске проверяются защищённый контекст (secure context), кросс-доменная
изоляция, SharedArrayBuffer, Worker и WebGL2. При отсутствии обязательных
возможностей кнопка Start блокируется с пояснением; при отсутствии Gamepad
отключается ввод USB. Неудачная проверка WebGPU сохраняет рендеринг WebGL2.
Доступность Web Serial API отображается отдельно: физический HITL (TASK-051) и
рендеринг WebGPU ещё не включены в активной полётной сессии.

## Быстрый запуск

TASK-042 предоставляет нативный интеграционный драйвер ArduCopter для Linux/WSL
(`scripts/sitl/driver.mjs` и sidecar pymavlink 2.4.50): закреплённая нативная
прошивка управляет синтетическим квадрокоптером quad X через наш WASM твёрдого
тела на Rust и интерфейсы JSON/MAVLink, а оцениваемый полёт и исходная
телеметрия проверяются скриптом `scripts/check-sitl-capture.mjs`. Этот автономный
стенд не изменяет браузерное демо и не доказывает измеренную аэродинамическую
достоверность ЛА. См. [процедуру SITL](runbook.md).

Используйте Node.js **22.13+** или **24 LTS** (`.nvmrc` выбирает 24), npm 10+ и
современный браузер Chrome/Edge на macOS или Windows. Будущий режим HITL через
Web Serial ориентирован на браузеры на базе Chromium. В облачных задачах
используется существующий изолированный checkout; не создавайте дополнительный
Git worktree без явного запроса.

```bash
cd /workspace/MirageSITL
npm ci
npm run dev
```

Для локального клона укажите фактический путь к рабочему каталогу. Сервер
разработки использует порт 5173. Для работы SharedArrayBuffer требуется
защищённый контекст: HTTPS или `localhost`. Удалённый доступ по HTTP и
IP-адресу не подходит. Серверы Vite `dev` и `preview` устанавливают эти
заголовки автоматически; production-хостинг обязан настраивать их самостоятельно:

```text
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Embedder-Policy: require-corp
```

Если домашний кеш в облачной среде недоступен для записи, добавьте
`--cache /workspace/.cache/mirage-npm` к команде `npm ci`.

### Демонстрационный полёт

Выберите **Start → Arm motors → поднимите Demo throttle выше 50%**. Задержка
раскрутки роторов введена намеренно. Пауза переводит двигатели в состояние
disarmed; перед повторным arm верните газ в ноль. Reset останавливает сессию и
возвращает модель на землю. Скрытие вкладки браузера ставит сессию на паузу.

Для аппаратуры EdgeTX/OpenTX выберите режим USB joystick на передатчике,
откройте вкладку ввода USB и сдвиньте стик, чтобы браузер обнаружил устройство.
Выберите устройство и проверьте направления каналов при выключенных двигателях.
Начальная раскладка осей 0/1/3/2 не является универсальной. Таблица калибровки
задаёт номер оси, минимум, центр, максимум и инверсию. Калибровка действует до
перезагрузки страницы. Демонстрационный ввод работает и без аппаратуры. На этом
этапе команды реальному полётному контроллеру не отправляются.

## Краткая архитектура

```text
Main Thread: Gamepad/calibration -> SAB pilot mailbox
Physics Worker: fixed-step demo -> SAB state ring
Main Thread: coherent snapshots -> interpolation -> R3F/HUD
```

```text
apps/web/             React UI, R3F view, Worker, runtime coordination
packages/protocol/    ABI v1/v2 and atomic readers/writers
packages/physics/     Demo dynamics and bounded scheduler
packages/input/       Gamepad adapter and calibration
packages/test-support/ Fixture integrity/provenance and deterministic PRNG
tests/                Unit and real-browser functional checks
docs/                 English specifications, roadmap, architecture
docs/ru/              Russian mirrors of system documentation
```

Поток физики владеет истинным состоянием и временем симуляции. Главный поток
отвечает за браузерный UI, ввод и рендеринг. Высокочастотные данные передаются
через SAB; сообщения жизненного цикла и ошибки — через `postMessage`. Кольцевой
буфер рендеринга хранит краткоживущую историю для интерполяции, а не архив AAR.
Будущие физические движки и адаптеры автопилота определены в спецификациях, а не
представлены пустыми неработающими заглушками.

## Проверка

```bash
npm run check:docs
npm run lint
npm run typecheck
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Устанавливайте браузер Playwright Chromium один раз и только при необходимости.
Подготовленная облачная машина может использовать системный браузер:

```bash
CHROMIUM_PATH=/usr/bin/chromium npm run test:browser
```

Модульные тесты проверяют ABI, планировщик, демонстрационную динамику, системы
координат и калибровку. Браузерные тесты запускают реальный Worker и SAB,
проверяют взлёт, паузу/сброс, имитацию подключения и отключения USB и мобильную
вёрстку. Тесты USB используют имитатор и не валидируют физический пульт или
Pixhawk.

После сборки команда `npm run preview -w @mirage/web` раздаёт production-бандл
на порту 4173. Проверьте наличие кросс-доменной изоляции, переход Worker в
состояние READY, движение после arm и неизменность счётчика тиков на паузе.
Доступны отдельные команды `lint` и `typecheck`. Для тестов WASM требуются Rust
1.97.0 и целевая платформа `wasm32`; команды toolchain приведены в
[CLAUDE.md](CLAUDE.md). GitHub Actions запускает независимые задания unit,
browser и build при pull request и push в `main`. Отчёты JUnit модульных тестов,
JUnit/HTML-отчёты и трассы сбоев браузера, а также логи и артефакты сборки
выгружаются даже при падении проверок. Автоматические проверки инструментов
включают фикстуры с небезопасными типами и проверку ненулевого кода возврата,
если любой из тестовых раннеров не обнаружил тестов.

400 Гц — это фиксированный **шаг численного интегрирования**, а не гарантия
жёсткого реального времени в браузере. Догоняющее выполнение (catch-up)
ограничено восемью шагами (`DEFAULT_MAX_CATCH_UP = 8`), а пропущенные интервалы
реального времени отображаются в UI. В Windows Node прогон `bench-physics` в
реальном времени выполнил 516.7 Гц (цель 800) и 519.6 Гц (цель 1200) с
пропусками: пробуждения таймера ~16 мс × лимит догоняющих шагов 8. Вычисление
занимает ~1 мкс/шаг; регрессия браузерного Worker на 800 Гц пройдена. Лимиты
catch-up и пороги пропусков нельзя ослаблять, чтобы скрыть потери. Целевые
60–120 FPS и 400–1200 Гц требуют измерений на целевом оборудовании Apple Silicon
M4 и RTX 4050 (TASK-073); безголовый облачный smoke-прогон эти бюджеты не
подтверждает.

## Модули физики, контакта и JSBSim

Независимые эталонные модели мотора, батареи, нагрузок произвольной рамы и
интегратора твёрдого тела RK4 доступны в `native/bet` вместе с реальным
WASM-адаптером твёрдого тела, атмосферой МСА/ветра (TASK-032) и набором
идеальных и зашумлённых датчиков (TASK-020–TASK-028, TASK-034, TASK-035).
TASK-033 добавляет конфигурируемый BET-backend NeuralFoil и производственную
привязку поляр/роторов, подключаемые через фабрику динамики PhysicsSessionV2
и проверенные в браузерном SAB Worker. Worker приложения по умолчанию
по-прежнему выбирает демонстрационную динамику.

Прямой `f64` C ABI контакта Rapier (`node scripts/build-contact.mjs`,
`node scripts/check-contact-binding.mjs`) проходит проверки нулевых аллокаций
G1 в native и WASM, синтетические тесты податливости и контакта и выполнение в
браузерном Worker (TASK-029). Опубликованные collision-чанки управляют контактом
Rapier с землёй через контактный ABI v2 (TASK-065): на каждом тике каждое колесо
и планер получают плоскость треугольника рельефа под собой, а отсутствие земли
приостанавливает шаги (подключение к полётной сессии и живой допуск рельефа
остаются открытыми).

Для JSBSim реализованы проверенная сборка WASM на Emscripten 4.0.15
(`node scripts/build-jsbsim.mjs`, проверка Worker smoke через
`node scripts/check-jsbsim-artifact.mjs` на 400/800/1200 Гц, TASK-030),
инструментированный контактный backend с нативными исключениями WASM
(`node scripts/build-jsbsim.mjs --contact`, проверки паритета native/WASM и
аллокатора через `node scripts/check-jsbsim-backend.mjs --native`,
`node --experimental-transform-types scripts/check-jsbsim-backend.mjs` и
`node scripts/bench-jsbsim.mjs`, TASK-031), а также проверенная загрузка таблиц
пропеллеров UIUC `<table name="C_T">` / `<table name="C_P">` в JSBSim v1.2.3
(`node scripts/check-jsbsim-propellers.mjs`, 18/18 случаев, TASK-086). XML
самолёта исключён из артефактов сборки. Явные нативные прогоны Rapier/JSBSim с
флагом `--patched` проходят миллион шагов с нулём аллокаций и совпадающими
контрольными суммами траекторий (`node scripts/check-engine-patch-parity.mjs`),
тогда как непатченные upstream-сборки продолжают выделять память. См.
[контракты реализации](SPECS_SIMULATION_ENGINES.md).

CLI валидации моделей (`node scripts/validate-models.mjs`) выводит численные
и runtime-результаты отдельно и возвращает код 2, пока измеренная физическая
достоверность остаётся открытой. Выбранная оператором синтетическая программная
база TASK-033 с NeuralFoil отделена от измеренной сертификации. Первая измеренная контактная
фикстура, `tests/fixtures/contact/nasa-drop.json`, содержит сбросы шасси на
горизонтальную поверхность из отчёта NASA TM X-3561
(https://ntrs.nasa.gov/citations/19780003109), сформированные скриптом
`tests/fixtures/contact/generate_nasa_drop.py` из хешированного архива Docling в
`tests/fixtures/contact/nasa/` с переводом в СИ. На этих данных сферический
контакт Rapier проходит проверки согласованности импульса, непроникания и
энергии, но не укладывается в измеренные огибающие замедления (`-1.6 g`) и хода
амортизатора; этот исторический провал сохранён в
`test-results/validation/nasa-drop-legacy.json`. Решение пользователя от
2026-10-18 отложить сравнение NASA явно зафиксировано в манифесте эталонов v2 и
схеме отчёта v5; достоверность контакта и кольцевой BEM пропеллеров UIUC
остаётся заблокированной до прохождения измеренной валидации, а не пройденной.

## Модули автопилота, каналов связи и РЭБ

TASK-037/038/039/040/048/052/053/056/057/060 предоставляют закреплённое
подмножество MAVLink2, версионированную калибровку и отображение режимов
радиоаппаратуры, допуск жизненного цикла автопилота, проверяемый по origin и
токену loopback-мост WS/UDP, транспорт Web Serial по жесту пользователя с
отдельным I/O Worker декодирования, изолированные компоненты РЭБ и отказов
моторов, а также политику рельефа с отказом по умолчанию. Запускайте
`npm run start -w @mirage/bridge` с локально заданным `MIRAGE_BRIDGE_TOKEN`
(64 шестнадцатеричных символа); необязательные `MIRAGE_BRIDGE_ORIGIN`,
`MIRAGE_MAVLINK_PORT` и `MIRAGE_PHYSICS_PORT` настраивают origin и UDP-порты.
Никогда не выводите токены в печать и не добавляйте их в URL или файлы
репозитория. Это только loopback `ws`; HTTPS/WSS/PNA требуют отдельной
интеграции. Используйте `node scripts/bench-links-ew.mjs all 400` (также
`800`/`1200`) для проверки аллокаций в Node, а не как аппаратную приёмку
таймингов. Скалярные вспомогательные методы могут упаковывать числа с плавающей
точкой: высокочастотная композиция использует входы и выходы на типизированных
массивах из спецификации движков.

TASK-043 соединяет `EkfMonitor` и 30-секундный допуск прогрева `LiveEkfWarmup` с
нативным SITL-драйвером Linux/WSL (TASK-042). Готовность определяется по
фактической диагностике автопилота и подтверждённым меткам времени датчиков,
измеряет ускорение симуляции и отзывает допуск РЭБ при нарушении свежести или
здоровья (`scripts/check-ekf-warmup.mjs`). Нативные эксперименты РЭБ TASK-059
используют закреплённую установку ArduCopter и синтетический квадрокоптер для
сбора шести сценариев, аудита сырых потоков и физики, однократной калибровки и
валидации относительно фиксированных пределов прошивки
(`scripts/check-ew-capture.mjs`). Эти автономные нативные проверки не включают
браузерный статус READY автопилота и не доказывают измеренную точность ЛА.

TASK-044 фиксирует требования нативного HAL ArduPilot, а TASK-045 предоставляет
локальную сборку и диагностику браузерного артефакта ArduCopter WASM
(`node scripts/build-ardupilot-wasm.mjs`), реальный запуск Worker/pthread и
проверки сохранения EEPROM в IndexedDB. Артефакт прошивки остаётся внешним со
статусом `BLOCKED_DECISION` (распространение GPLv3) и раздаётся только при явной
loopback-настройке разработки; см. [эксплуатационное руководство](runbook.md).
Активным полётным backend в браузере остаётся demo, пока TASK-046 и TASK-047
интегрируют и проверяют транспорт и паритет полёта прошивки WASM.

## Тепловой конвейер, консоль инструктора, AAR и инструменты приёмки

Демо включает авиагоризонт NED с явной индикацией неизвестного или устаревшего
статуса автопилота, консоль инструктора с подтверждением команд (ACK) и
ограниченный регистратор сессии. Нажмите **Start recording**, выполните полёт в
демо, затем выберите **Review recording** или **Export session**. **Import AAR**
открывает проверенную шкалу снимков без замены активного полёта. Запись
выполняет прореживание истинного состояния и ввода пилота в главном потоке с
номинальной частотой 10 Гц; потоки датчиков и актуаторов полётного контроллера в
демо недоступны. 30-минутный кольцевой буфер использует 9,216,000 байт записей с
отдельным учётом потерь и вытеснения. Размер архива ограничен 32 МиБ, а
произвольные метаданные, ключи и серийные идентификаторы исключены. Измерение
аллокаций производителя записи выполняется командой `node scripts/bench-aar.mjs 400`
(повторить для `800`/`1200`).

Горячие клавиши инструктора: P — пауза, R — сброс, F — выбранный отказ; при
фокусе в поле ввода клавиши подавляются. Запросы погоды, отказов и смены модели
показывают фактическое отклонение демонстрационным backend до подключения
рабочего backend (TASK-074/075/078). Тепловой пакет предоставляет синтетический
решатель поверхностного баланса энергии, WebGL2 LWIR-материал и детерминированную
калибровку смещения, протестированные независимо от активной сцены; измеренная
точность уровня CADEX не заявляется.

Репозиторий также включает построение и владение collision-чанками рельефа,
детерминированное расписание и рубрики сценариев
(`node scripts/bench-terrain-scenarios.mjs 400`, `800`, `1200`) и локальные
CLI-анализаторы свидетельств SITL/HITL/РЭБ/GPU/системы/выпуска. Пользователи
клавиатуры могут переходить к элементам управления и получают видимый фокус и
однократное оповещение об отказе в разрешении; браузерный набор включает
проверку axe без отключённых правил и тесты переполнения/фокуса Serial при
ширине 390 px (TASK-079). Команды, форматы внешних трасс, правила владения
процессами и чеклист доступности документированы в [руководстве](runbook.md). Все
CLI-анализаторы без входных данных завершаются с кодом 2 (`BLOCKED_EXTERNAL`) и
заблокированным отчётом; физические полётные контроллеры (TASK-051), целевые GPU
(TASK-073), многочасовой прогон (TASK-082) и выпускная проверка на чистой машине
(TASK-083) остаются открытыми, а публикация никогда не выполняется автоматически.
