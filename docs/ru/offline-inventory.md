# Инвентаризация офлайн-зависимостей и рельефа

<!-- source-sha256: a26bb336f005aa7aa2d0d3a845c16b55a0613b7dc010d42684793ba2e6ea03e7 -->

Русское зеркало. [Английский источник](../operations/offline-inventory.md).

TASK-131 (S01, S17). После установки рабочий процесс фазы 1 должен работать
офлайн (S01), а рельеф ограничен уже существующими локальными данными с
акцентом на Израиль (S17). Это руководство перечисляет, что нужно фазе 1 после
установки, какие источники данных существуют и чего не хватает. Оно не
добавляет поставщиков и ничего не загружает.

## Файлы и проверка

| Файл | Содержимое |
| --- | --- |
| `config/offline-inventory.json` | Строки зависимостей, перечисленные сетевые origin, политика лицензий npm и сканируемые каталоги |
| `data/terrain/inventory.json` | Источники рельефа, снимков и земного покрова, а также пробелы покрытия |
| `scripts/check-offline.mjs` | Проверка; она читает только локальные файлы |

```bash
node scripts/check-offline.mjs
npm run build
node scripts/check-offline.mjs --dist apps/web/dist
```

Проверка печатает сводку JSON и завершается с кодом 0 при PASS и 1 при FAIL.
Она падает, если:

* сканируемый файл или собранный бандл называет сетевой origin, которого нет в
  `networkOrigins`;
* runtime-пакет npm (не для разработки) в `package-lock.json` объявляет
  лицензию вне `npm.allowedLicenses` или не объявляет лицензии;
* инвентаризованный файл отсутствует или его размер в байтах либо SHA-256
  отличаются;
* неразрешённая или ограниченная лицензия, ожидающая зависимость или
  неготовый источник рельефа не называют решение или задачу, которые их
  разрешают;
* категория, вид рельефа, значение готовности или обязательное поле
  неизвестны или отсутствуют;
* `--dist` указывает несуществующий каталог бандла.

Сканирование охватывает `apps`, `packages`, `services`, `scripts`, `config`,
`data` и `native` (файлы TypeScript, JavaScript, HTML, JSON, Python и shell) и
пропускает `node_modules`, `dist`, `target`, `.cache` и `.git`. Проверка видит
только origin, записанные буквально в виде `scheme://host[:port]`. URL,
собираемые во время выполнения из конфигурации, например
`VITE_MIRAGE_TILESET_URL`, ей не видны; эти источники регулирует TASK-186.

`tests/offline-inventory.test.ts` запускает проверку на репозитории и на
небольших синтетических корнях, нарушающих каждое правило, включая
синтетический бандл.

## Назначения сетевых origin

| Назначение | Смысл |
| --- | --- |
| `loopback` | Только локальная машина: мост, серверы предпросмотра и проверки Worker |
| `identifier` | Идентификатор схемы или пространства имён, который никогда не загружается |
| `documentation-link` | Ссылка на источник или документацию в комментариях, манифестах данных или встроенных библиотеках |
| `install-time` | Загружается при установке или сборке: клоны закреплённых исходников и реестры пакетов |
| `manual-data-preparation` | Загружается только тогда, когда оператор вручную запускает скрипт подготовки данных |
| `online-optional` | Онлайн-сервис, который никогда не является офлайн-источником и не является готовым источником без ключей и развёртывания |

Файл инвентаризации сам называет каждый перечисленный origin, поэтому
проверка его не сканирует; поле сводки `unusedOrigins` перечисляет origin,
которые не называет ни один сканируемый файл. 2026-10-28 сканирование
репозитория нашло 23 из 27 перечисленных origin: 5 loopback, 4 идентификатора,
7 ссылок на документацию, 2 install-time, 4 для ручной подготовки данных и 1
online-optional (`https://tile.googleapis.com` за необязательным tiles
worker). Собранный бандл добавляет остальные 4, все внутри встроенных
библиотек: идентификатор `http://www.w3.org` и ссылки на документацию
`https://react.dev`, `https://docs.pmnd.rs` и `https://www.shadertoy.com`.
С `--dist apps/web/dist` названы все 27 и неиспользуемых нет.

## Источники рельефа

Снимки, высоты и земной покров — отдельные виды. Источник, которому нужны
данные, ключи или развёртывание, не является готовым источником.

| Источник | Вид | Покрытие | Разрешение | Готовность | Статус лицензии |
| --- | --- | --- | --- | --- | --- |
| Синтетическая ровная площадка | Синтетическая поверхность | Любое место | Аналитическая плоскость | Готово | Неприменимо |
| ESA WorldCover 2021 v200 | Земной покров | Только Израиль (тайлы N27E033, N30E033, N33E033) | Классы 10 м | Готово, не подключено к runtime | Проверена (CC BY 4.0) |
| FABDEM V1-2 | Высоты | Ограничивающий прямоугольник `config/geodata.json` после подготовки | Около 30 м | Нужны данные | Проверена (CC BY-NC-SA 4.0; некоммерческое использование) |
| Сетка геоида EGM2008 | Геоид | Весь мир | 2,5 угловой минуты | Нужны данные | Проверена |
| Здания Overture Maps | Векторные объекты | Прямоугольник после подготовки | Контуры с высотами | Нужны данные | Проверена (ODbL-1.0 или CDLA-Permissive-2.0) |
| Объекты OpenStreetMap | Векторные объекты | Переданная выгрузка | Векторные | Нужны данные | Проверена (ODbL-1.0) |
| Google Photorealistic 3D Tiles | Снимки и сетка | Только онлайн | Определяется поставщиком | Нужны ключи или развёртывание | Ограничена (условия Google Maps Platform) |
| Тестовые данные quantized-mesh | Тестовые данные | Синтетическое | Уровни 0–12 | Только для тестов | Неприменимо |
| Тестовые данные 3D Tiles | Тестовые данные | Синтетическое | Геометрия тестовых данных | Только для тестов | Неприменимо |

Три тайла WorldCover находятся в репозитории, и проверка сверяет их размер и
SHA-256 при каждом запуске. Результаты FABDEM, геоида и зданий готовятся
вручную с помощью `scripts/geodata/` и хранятся вне репозитория.

## Пробелы покрытия

Пробелы перечислены, а не закрыты новыми поставщиками:

1. Офлайн-снимков нет ни для одного региона. Единственный источник снимков —
   онлайн-прокси Google, которому нужны ключи и развёртывание.
2. Данных о высотах в репозитории нет. Инструменты FABDEM существуют, но их
   результат готовится вручную, хранится вне репозитория и лицензирован только
   для некоммерческого использования.
3. Земной покров WorldCover для Израиля проверен, но не подключён к runtime.
4. Сетки геоида в репозитории нет, поэтому высоту над уровнем моря пока нельзя
   офлайн перевести в эллипсоидальную высоту (TASK-148).
5. Вне тайлов WorldCover для Израиля и вне локально подготовленной области
   FABDEM доступна только синтетическая площадка.

## Решения по этой инвентаризации

Решение D-09 в [плане фазы 1](PHASE1_PLAN.md) принято 2026-10-28: MirageSITL —
некоммерческий проект. Поэтому FABDEM, сетка геоида EGM2008, здания Overture,
объекты OpenStreetMap и данные пропеллеров UIUC можно использовать так, как
указано, а вопросы о лицензиях стейкхолдеру больше не задаются; факты о
лицензиях фиксируются здесь. Google Photorealistic 3D Tiles остаются только
онлайн-источником и не считаются готовыми, потому что им нужны ключи и
развёртывание, а их условия запрещают офлайн-кэширование.

Остальные открытые строки ждут задач, а не ответов о лицензиях: D-01 и D-02
(версия ArduPilot и способ сборки на macOS), D-04 (UAVLogViewer, TASK-130),
TASK-148 (файлы WMM и геоида) и TASK-159 (метаданные параметров).

## Сопровождение инвентаризации

* Новому сетевому origin нужна строка с назначением и причиной. Загрузка во
  время выполнения с не-loopback origin имеет назначение `online-optional` и
  требует проверки по S01.
* Runtime-пакет npm с новой лицензией приводит к падению проверки, пока
  лицензия не проверена и не добавлена в `npm.allowedLicenses`.
* Обновляйте размер и SHA-256 файла только после сверки нового файла с его
  источником. Никогда не обновляйте их лишь для того, чтобы заглушить проверку.
* Обновляйте русское зеркало в том же изменении.
